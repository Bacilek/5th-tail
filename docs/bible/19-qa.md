# 19 - QA and testing

Biggest current risk: the game has never been run in a real browser by me; every claim so far is "builds + code reads right". Phase 0 fixes that.

## Automated checks (to build)
1. `npm run build` (typecheck + bundle) - exists.
2. **Smoke test** (Playwright + Chromium, headless with WebGL via SwiftShader or headed): start dev server, open page, create character, pick class, wait for game start, assert no console errors, take screenshots at fixed spots (spawn, Parapet, Citadel, Flight Field), assert FPS above a floor (relaxed in headless).
3. **Scenario tests** using `window.__game` debug hooks: teleport, spawn enemy and fight, start/complete a quest via console, mount broom/dragon, open map, save/load round trip.
4. **Unit tests** (Vitest): quest state machine, dragon rolls (statistical test of weights), collision helpers, save migration, data validators.
5. **Data validators**: unknown ids in quests/NPCs/pois, unreachable quest stages, items without models.
6. **Visual regression** (SHOULD): compare screenshots to baselines with tolerance.

## Manual playtest checklists
### Smoke (every milestone)
- Start: create character -> class -> spawn; movement, jump, sprint, camera toggle.
- Combat: swing, cast, block (after Phase 1), take damage, die, respawn.
- Interact: talk, quest accept/complete, pickup.
- Vehicles: broom mount/dismount/race; dragon summon/mount/flight/dismount.
- Parapet crossing; Gauntlet; Threshing.
- UI: map, waypoint, quest log, settings, pause.
- Audio on/off, day/night transitions, performance.

### Edge cases
Dialogue + map open; death while mounted; stuck in geometry; falling out of the world; very high altitude; rapid class/character switching; resizing the window; losing pointer lock; gamepad hot-plug; localStorage disabled.

## Bug workflow
Bug list in `docs/bugs.md` (id, steps, expected/actual, severity, found-in-milestone, status). Fix before adding features when severity >= major. Add a regression test for each fixed major bug when feasible.

## Performance profile steps
Chrome Performance panel: frame time, GC spikes, draw calls (`renderer.info`), memory heap snapshots, long tasks; test Low/Med/High presets; test on a weaker laptop.

## Release gate for each milestone
Build passes, smoke test passes, playtest checklist done by a human (Marek/partner) with notes in `docs/playtests/YYYY-MM-DD.md`.

## Decisions
Playtest after every milestone (15-30 min, notes in `docs/playtests/`). Test device: Ryzen 7 7735HS / Radeon 680M (see 16).
